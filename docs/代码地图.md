# 代码地图 · 桌面版 Repy

> 这份只管**桌面版**：**要改的东西在哪**。功能怎么用看 [README](../README.md)，打包细节看 [BUILD-MAC.md](BUILD-MAC.md)。行号会漂，所以正文只写函数名，精确行号看文末自动附录（`npm run where -- --gen` 现算）。
>
> **小程序 RepyNeo 是另一个工程**：`repyneo/` 下 4 页 + 5 个 utils，看 [代码地图-Neo.md](代码地图-Neo.md)。两个工程共用同一套 `npm run where` 定位器。

## 两个工程，别改错文件

| | 桌面版 Repy | 小程序 RepyNeo |
|---|---|---|
| 版本 | 2.1.1 | 1.0.2 |
| 代码 | `src/index.html` 单文件（约 1.28 万行） | `repyneo/` 多文件 |
| 索引 | 本文件 | [代码地图-Neo.md](代码地图-Neo.md) |
| 自检 | `scripts/check.js` | `npm run check:neo` |
| 版本号 | `npm run bump x.y.z`（9 个位置） | 手改三处，不归 bump 管 |

两边共用 `fitness-log-*` 数据键与动作 id，能互导记录与偏好；改动作池时注意对齐。

## 三层结构

```
壳   main.js（窗口、热更新、升级、AI 接口）  preload.js（IPC 白名单）
 └── 渲染   src/index.html（桌面版唯一要改的业务文件）
             ├─ <style>   样式，按版本划分区
             ├─ HTML      三个 <main> + 各类弹窗 / 面板
             └─ <script>  全部逻辑，无模块、无构建
工具 scripts/  打包、自检、图标、双工程定位器
```

改桌面版界面 = 只改 `src/index.html`；改小程序 = 只改 `repyneo/`。根目录那个 `通用版 · 健身记录生成器.html` 是原件，不参与运行，别动。

## 找东西三步（省积分的关键）

```bash
npm run where 气泡                  # 1. 两个工程一起搜：命中行 + 所在函数 / 分区 / 行号
npm run where 气泡 -- --neo         #    只搜小程序；--desk 只搜桌面版；--all 列全
                                    # 2. 只读命中的那个函数（一般 30–80 行）
npm run where -- --fn 设置          # 函数 / 方法总表（可按名字过滤）
npm run where -- --css             # CSS / WXSS 分区清单
npm run where -- --tree            # 项目结构总览：文件 · 行数 · 职责
npm run where -- --gen             # 行号漂了：一次重算两份地图的自动附录
```

拿到函数名后按名定位，别按行号记 —— 行号每次改都会漂。小程序那半边看 [代码地图-Neo.md](代码地图-Neo.md)。

## 版本号：只有一处入口

版本号散在 4 个文件的 10 个位置，手改必漏。用：

```bash
npm run bump 2.1.2
```

会同步：`package.json.version`、`update.json.version`、`index.html` 的 `<title>`、`versionChip`、`APP_VERSION`、`RELEASE_VERSION`、气泡的「V x 新东西」标签、以及 `check.js` 里两处 mock 加文案。**只收三段式**——四段号（`2.1.1.1`）electron-builder 会报 `Invalid version` 直接拒，打不出包。改完自己看一眼 `git diff`。

`update.json` 的 `notes` 是手写的人话，脚本不动它，记得自己补。

## 两条必须遵守的样式规则

1. **新 CSS 追加在 `</style>` 之前最后位置**。前面几轮为了压过旧规则用了大量 `!important`，写早了会被压回去。
2. **颜色改两处**：CSS 的 `.group-胸/背/腿/肩` + JS 的 `GROUPS[].color`，只改一处会出现「卡片色变了、标签没变」。

## 改完怎么验

| 改动大小 | 验法 |
|---|---|
| 文案、间距、颜色 | 开着 `1-开发预览.bat` 的窗口，存盘 0.1 秒就变 |
| 小程序任何改动 | `npm run check:neo`（JSON / 语法 / wxml 绑定的方法 / 断言），再看开发者工具「编译」后的界面 |
| 桌面版结构 / 交互 | `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS npx electron scripts/check.js`，看 `runErrors` 是不是空、`build/check-*.png` 有没有错位 |
| 打包相关 | `2-打包出exe.bat` 重新出包，`dist/` 里的是打包那一刻的快照 |

`check.js` / `check-repyneo.js` 里的断言是照着**当时**的界面写的，大改布局时断言先失败是正常的，顺手把断言改成符合新布局的即可；但「wxml 绑定的方法必须存在」这类结构性断言永远不能删。
